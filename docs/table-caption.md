# 表のキャプション

Markdown の表には、原則として内容を表すキャプションを付けます。  
見出しや直前の本文だけに頼らず、表が何を比較・列挙しているかを短い表題で示します。  
表題は「一覧」「比較」だけで済ませず、対象と観点が分かる名前にします。  
記法の説明中でキャプションのない表を示す場合など、付けると例の意図が変わるときは省略できます。

表のキャプションは、表の直前に `Table:` 段落を記述して指定します。  
`Table:` 段落と表の間には空行を挿入します。  
表の後ろの段落や見出しとの間にも空行を挿入します。  
キャプションは静的発行と動的発行のどちらでも表の上に表示され、本文カラム幅で折り返されます。  
箇条書きの項目の中では、`Table:` 段落を表と同じ字下げにします。  
トップレベルの項目は 4 スペース、1 段ネストした子項目は 8 スペースです。  
書き方の例は [箇条書きの項目に入れる表](sample/list-table.md) を参照してください。

```markdown
Table: 表のキャプション {#tbl:sample}

| 項目 | 値 |
|---|---|
| A | B |
```

キャプションの末尾に `{#tbl:xxx}` を記述すると、pandoc-crossref による採番と相互参照の対象になります。  
ラベルがない場合も、キャプションの位置と表示は同じです。  
キャプションの接頭辞は `Table:` だけです。`table:` と、行頭の `:` だけの短縮形はキャプションとして扱いません。

## キャプションとして扱う条件

`Table:` 段落は、次のすべてを満たす場合に、直後の表のキャプションになります。

1. 段落の先頭が `Table:` で始まる。
2. 段落の直後のブロックが表である (間に空行を挟む)。
3. 段落と表の字下げの幅が一致する。
4. 段落、間の空行、表が、同じ深さのブロック引用の中にある (または、いずれも引用の外にある)。

ブロック引用 (行頭の `>`) の中でも、引用の外と同じ規則で扱います。  
判定と字下げの比較は、行頭の引用の記号 (`>` と直後の空白 1 個の繰り返し) を除いた内容で行います。引用の深さは `>` の数です。  
`> [!NOTE]` などのアラート記法の中に表を置く場合は、アラート記法の行と `Table:` 段落の間に空行 (`>` だけの行) を挟みます。

```markdown
> [!NOTE]
>
> Table: 引用の中の表のキャプション
>
> | 項目 | 値 |
> |---|---|
> | A | B |
```

表が連続する場合も、`Table:` 段落は常に直後の表のキャプションです。

```markdown
Table: 1 つ目の表

| 項目 | 値 |
|---|---|
| t1 | 10 |

Table: 2 つ目の表

| 項目 | 値 |
|---|---|
| u1 | 30 |
```

### キャプションとして扱わない場合

条件を満たさない `Table:` 段落は、Pandoc 発行と MkDocs 発行のどちらでも通常の段落として出力し、標準エラー出力へ警告を出します。  
表の直後に置いた `Table:` 段落も、その直後に表がなければこの扱いです。  
`Table:` 段落と表の間に空行がない場合は、表が段落の一部として解析されるため、キャプションにも表にもなりません。  
アラート記法の行の直後に空行を挟まずに書いた `> Table:` は、段落の先頭ではないため、キャプションになりません。  
引用の深さが異なる行 (`>` のない遅延継続行を含む) が `Table:` 段落、間の空行、表に混ざる場合も、キャプションになりません。

## 複数行のキャプション

`Table:` と同じ段落内で改行すると、HTML、DOCX、MkDocs の出力でも改行が保持されます。  
ラベルを付ける場合は、最後の行の末尾に `{#tbl:xxx}` を記述します。  
書き方と出力例は [表のキャプションのサンプル](sample/table-caption.md) を参照してください。

## HTML の構造

Pandoc HTML と MkDocs は、どちらもキャプション ブロックと `table` が隣り合う構造で出力します。  
Pandoc HTML のキャプションは `div` 要素です。

```html
<div class="docsfw-caption docsfw-table-caption">表のキャプション</div>
<table id="tbl:sample">...</table>
```

MkDocs のキャプションは、同じクラスを持つ `p` 要素です。ラベルを指定した場合、id もこの `p` 要素に付与されます。  
Material for MkDocs の JavaScript 実行後は `table` が `.md-typeset__table` と `.md-typeset__scrollwrap` に囲まれます。  
要素種別やラッパーの有無にかかわらず、キャプションは表の上に置き、キャプションと表の間隔を 8px にします。  
キャプションの行高とインライン コード、および表のフォント、セルの内余白、罫線、最小幅も両発行系で同じ値にします。

表の罫線は、交点で色が重ならない不透明色です。  
外枠と内罫線はどちらも 1px とし、外枠を内罫線より高いコントラストで表示します。  
ライト配色では外枠を `#969696`、内罫線を `#b5b5b5`、ダーク配色では外枠を `#858890`、内罫線を `#70747e` にします。

## 処理の流れ

### Pandoc 発行

`pub_markdown_core.sh` は、Markdown 本文を Pandoc に渡す前に、前処理 `bin_internal/table-caption-preprocess.py` を通します。  
Pandoc は既定の `table_captions` 拡張で `Table:` 段落を表のキャプションとして取り込みます。  
ただし Pandoc は表が連続すると後置きのキャプションを優先するため、前処理が前置きの `Table:` 段落を表の後ろへ並べ替えます。

前処理は、次の規則で本文を書き換えます。判定は `table_caption_position.py` の `prepare_for_pandoc()` です。

- 空行を挟んで直後に同じ字下げの表が続く `Table:` 段落は、キャプションとして扱い、その表の後ろへ移します。表が連続する場合も、元の行の順序で帰属を決めます。
- それ以外の `Table:` 段落は、通常の段落として出力するため `Table\:` にエスケープし、標準エラー出力へ警告を出します。
- 表の直前または直後にある行頭 `table:` と `:` の段落は、Pandoc がキャプションとして取り込まないよう、コロンをエスケープします。この場合は警告を出しません。
- ラベルの接頭辞が `tbl` 以外の場合は、警告を出したうえで、そのラベルを採用します。
- フェンス付きコード ブロックと HTML コメントの中は変更しません。処理中に例外が発生した場合は、入力をそのまま出力します。

接頭辞 `Table:` と前後の空白を除いたインライン列がキャプション、末尾の `{#tbl:xxx}` が identifier です。  
段落内の改行は保持します。  
箇条書きの項目やブロック引用の中の表にも、同じ処理を適用します。

> [!NOTE]
> `Table:` 段落を Lua フィルターで表へ畳み込む方式では、`Table:` が解析の時点で通常の段落になります。
> Pandoc は箇条書きの項目に段落が 1 つでもあるとリスト全体を段落ごとの表示にするため、項目内の表の前に `Table:` を置くだけで表示が変わります。
> 前処理で元の行の順序から帰属を決めて後置きに並べ替えれば、Pandoc の解析結果は表の後ろに書いた場合と同じになります。

`codeblock-caption-line.lua` は `Table:` 段落を扱いません。pandoc-crossref は、取り込まれた表の identifier とキャプションから採番します。  
HTML では、pandoc-crossref の後に `table-caption-style.lua` を適用し、採番済みのキャプションを `div.docsfw-caption.docsfw-table-caption` として `table` の直前へ出します。  
表の identifier は `table` に残ります。pandoc-crossref がない場合も同じフィルターがキャプションを出力します。  
DOCX では、Pandoc が表のキャプションを表の前に出力します。

```text
table-caption-preprocess.py (Pandoc の前)

fix-line-break.lua
  -> codeblock-caption-line.lua
  -> ... (中略)
  -> pandoc-crossref
  -> listing-caption-style.lua
  -> table-caption-style.lua
```

### MkDocs 発行

`stage_livedocs.py` の `convert_captions()` は、空行を挟んで直後に同じ字下げの表が続く `Table:` 段落を、その位置のまま `.docsfw-caption .docsfw-table-caption` クラスとラベルの id を付けた段落にします。  
ブロック引用の中の `Table:` 段落にも同じクラスを付けます。変換後の段落と属性行には、元の引用の記号を保ちます。  
条件を満たさない `Table:` 段落は、警告を出し、クラスを付けない通常の段落としてその位置に残します。
