# ファイル目次は開いている階層だけ DOM に生成する

Pandoc HTML と MkDocs のファイル目次は、ツリー全体をデータとして保持し、開いている階層だけ DOM に生成します。  
枝を閉じると子 DOM を破棄し、再展開時には保存した展開状態から作り直します。  
本文中の `\toc` による索引リストと、ページ内の見出し目次は、この遅延生成の対象外です。

## DOM と展開状態を分けて保持する

初期表示ではルート直下の項目を生成し、現在ページへ至る経路だけを開きます。  
開いている各枝には直下の項目を生成しますが、閉じた子の子孫は生成しません。  
子孫の展開状態は親を閉じても保持するため、再展開時には以前開いていた階層を復元します。  
閉じた枝の DOM を別のコンテナーや `DocumentFragment` に保存するキャッシュは作りません。

全項目数を N、現在表示する項目数を V とすると、データと展開状態の保持は O(N)、目次の DOM 数は O(V) です。  
この変更では、全体データの転送と解析に必要な O(N) の処理は残ります。  
同じ階層に多数の兄弟がある場合は、その階層の展開時に全兄弟を生成するため、表示範囲だけを描画する仮想スクロールを別途検討します。

## Pandoc は既存のツリー データから必要な枝を描画する

`styles/html/docsfw-nav.js` は、既存の `nav-tree.js` に含まれる `title`、`url`、`path`、`children` を使います。  
生成データの形式と、`file://` からの読み込み方法は変更しません。

初期化時にツリーを一度走査し、現在ページとその祖先を `WeakSet` に記録します。  
枝の展開状態も別の `WeakSet` に保持し、初期値を現在ページの経路から設定します。  
子パネルを検索するための対応表は、ノードからパネル キーを引く `WeakMap` とします。  
これにより、各ノードで子孫を繰り返し検索する処理と、子パネルを探すたびに全パネルを走査する処理を除きます。  
対応表に DOM 要素は保持しません。

### 一覧では展開時に子を生成し、折りたたみ時に破棄する

`renderFlatNode` は、項目の行と開閉ボタン、子を入れる空の `ul` を生成します。  
展開状態の枝に限り、子を再帰生成します。  
現在ページの祖先を示す強調は、手動で展開した状態と区別します。

開閉ボタンのイベントは、置き換えない `#docsfw-tree` で受けます。  
展開時には直下の子を生成し、保存された子の展開状態も復元します。  
折りたたみ時には子 DOM と、破棄した子の一時的な枝 ID の対応を除去します。  
親の行とボタンは残すため、通常のボタン操作ではフォーカスも残ります。  
ボタンの `aria-expanded` は子の表示状態に合わせて更新します。

### 狭幅では表示中のパネルを一枚だけ生成する

76.234375em 以下では、表示中の階層の項目と戻る見出しだけを DOM に生成します。  
全階層のパネルや一覧形式のツリーは同時に生成しません。  
子階層へ進む操作と戻る操作は、データ上のパネル キーを使って表示中のパネルを置き換えます。  
キーボード操作で移動した場合は、生成した階層見出しへフォーカスします。

画面幅が境界を越えたときは、同じデータから一覧またはパネルを再生成します。  
一覧の展開状態は維持し、パネル形式へ入るときは現在ページの階層を表示します。  
ページ内目次が置き換える DOM に含まれる場合は、目次をコンテナーの外へ退避してから再生成し、既存の配置処理で戻します。  
目次のリンク要素を維持するため、現在見出しの追従処理も継続します。

## MkDocs は項目の HTML を文字列データとして保持する

`livedocs/theme/partials/nav.html` は、現在ページの言語と詳細度に対応するツリーだけを扱います。  
`nav-item.html` の初期 HTML 出力では、現在ページの経路に限って子項目を再帰生成します。  
別の枝には、その枝の行と空の子一覧だけを出力します。  
Material の `input`、`label`、`nav` の構造とクラスを維持するため、既存の配置とスライド操作を利用できます。  
狭幅でも、開いている経路の祖先と、その各階層の直下項目は入れ子構造として残します。

全体データは `#docsfw-nav-data` の `application/json` に格納します。  
各項目は次の値を持ちます。

- `id`: Material のチェック ボックスと同じ階層 ID
- `html`: 子項目を含まない、その項目の行と空の子一覧の HTML 文字列
- `expanded`: 現在の展開状態。初期値は現在ページの経路
- `children`: 子項目データの配列

行の HTML は既存の描画マクロを浅い出力で呼び出して作るため、リンク、索引ページ、アイコン、タイトルの規則を二重に実装しません。  
各項目の URL は、そのページを生成する時点で相対 URL に変換します。  
JSON は Jinja の `tojson` で出力し、タイトルや HTML 内の `</script>` によってデータ要素が閉じられないようにします。  
文字列から DOM を生成するときにも、テンプレートが処理した HTML だけを使います。

### 動的に作った項目にも開閉イベントを適用する

`livedocs/assets/docsfw-responsive-nav.js` は JSON を解析し、ID から項目を引く対応表を作ります。  
初期化済みの同じデータ要素は再解析せず、ページのデータ要素が変わった場合は対応表を作り直します。

チェック ボックスの `change` を捕捉フェーズで受け、Material と目次配置処理が新しい階層を参照する前に子を生成します。  
生成対象は直下の子と、保存された状態で開いている子孫です。  
子を生成する際の `template` と `DocumentFragment` は一時的に使い、生成後は保持しません。  
折りたたみ時には展開状態を更新し、子一覧を空にします。  
子の展開状態は項目データに保持するため、DOM の再生成後にチェック状態を復元できます。

動的に追加したラベルも Enter と Space で開閉できるよう、キーイベントを委譲します。  
このキー操作は捕捉フェーズで完結させ、Material のキー処理との二重反転を防ぎます。  
各 `nav` の `aria-expanded` も展開状態に同期させます。

### 閉じる枝の目次とフォーカスを先に移す

統合したページ内目次が閉じる枝にある場合は、更新後のチェック状態から表示階層を求め、親の一覧へ目次を移します。  
その後で子 DOM を破棄するため、目次の要素と追従状態を維持できます。  
破棄する DOM にフォーカスがある場合は、残る親の開閉ラベルへフォーカスを移します。  
画面幅による目次の左右移動は、既存の配置処理を使います。

## 転送量と発行時の処理は別に評価する

MkDocs の JSON は各ページに埋め込むため、全体データの転送と発行時のテンプレート走査は残ります。  
HTML 文字列の JSON エスケープと、初期表示部分の重複により、転送量は旧方式より増える場合もあります。  
この設計による削減対象は、未展開部分の HTML 解析、DOM 生成、DOM 保持と、展開操作時に影響する DOM の範囲です。  
ツリーを共通ファイルへ分離する方式は、ページ相対 URL と現在ページの状態を別途組み立てる設計が必要です。

## 局所 fixture で DOM の増減と操作を検証する

`bin_test/test_lazy_nav_browser.js` は、Pandoc の千項目規模のデータと、MkDocs の複数階層・両詳細度を含む局所サイトを使用します。  
MkDocs の局所サイトは `mkdocs build --strict` で生成します。  
実ブラウザーでは、初期 DOM 数、現在ページの経路、動的な子と孫の展開、折りたたみによる DOM 除去、再展開時の状態復元を確認します。  
画面幅の変更、パネル数、ページ内目次の維持、Enter と Space による動的ラベルの操作も検証対象です。

実行ディレクトリは docsfw ルートです。

```bash
node bin_test/test_lazy_nav_browser.js
```

Puppeteer は既存の Node コンポーネント探索処理で解決します。  
Python とブラウザーの実行ファイルは、必要に応じて `PYTHON` と `PUPPETEER_EXECUTABLE_PATH` で指定します。  
生成した局所サイトは一時ディレクトリに配置し、終了時に除去します。
