# 日本語技術文書の文章規範

## 適用範囲

この文書は、リポジトリの第一者管理の日本語技術文書、解説、設計、手順、ソース コード内のコメント、メッセージ定義などを作成または推敲するときに適用します。  
機械的な空白、表記、Markdown 構造は [text_style_jp](../bin/text_style_jp.md) を参照してください。  
文脈に応じて判断が必要な言い回しや用語の選択は、機械処理に委ねずこの規範に基づいて推敲します。

### 対象外とするもの

- **外部由来のファイル**: 外部 OSS、サード パーティーのライブラリ、外部配布物、ベンダー資産などは、原則として推敲や直接修正の対象外とします。
- **自動生成された成果物**: ビルド成果物、Doxygen や Pandoc、MkDocs による生成 HTML、Word (docx)、自動生成 Markdown などは直接編集の対象外とします。自動生成される文章に問題がある場合は、生成物そのものを直接修正するのではなく、その生成元となるテンプレート、スクリプト、ソース コード、定義ファイル側に対策を施します。

## 文体と整形

本文段落は、です・ます調で記載します。  
見出し、短いリスト項目、表のセル、コード、引用には、名詞句や常体を使用できます。  
同一のリストや表の内部では文体を統一し、項目ごとにです・ます調と常体を混在させません。

原則として一文を一行に記載します。  
表示幅を調整するために文の途中で改行せず、段落の区切りには空行を使用します。

コード、ログ、設定、コマンドはコード ブロックへ置きます。  
ファイル ツリーには ASCII 記号を使用し、全角幅になり得る罫線文字を使用しません。

## 段落

一つの段落では一つの論点を扱います。  
段落の最初の文で、その段落が説明する対象を判断できるようにします。

結論、根拠、例の関係を明確にし、同じ結論を言い換えて繰り返しません。  
複数の原因や条件がある場合は、それぞれを区別して対応関係を示します。

因果を述べる場合は、結果だけでなく、その結果になる仕組みを簡潔に記載します。  
検出、保証、解決が条件付きである場合は、その条件を省略しません。

## 読み手の負荷

後で参照しない固有名、行番号、ログ値を導入しません。  
永続的な参照が必要な場合は、行番号ではなくファイル、見出し、シンボルを使用します。

用語は最初に意味と適用範囲を示し、以後は同じ語を使用します。  
同じ概念に複数の呼び方を混在させません。

## 表現

内容を伴わない強調や予告を使用しません。  
「重要なのは」「包括的に」「深掘りする」などの表現は、具体的な主張へ置き換えます。

比喩や作業者だけに通じる略語を避け、対象と操作を具体的に記載します。  
確認していない内容は、確認済みであるかのように断定しません。

口語や擬人化表現を避け、システムの振る舞いやデータ構造を客観的かつ具体的に記載します。  
「抱え込む」は「保持する」「管理する」、「口」は「API」「インターフェース」「関数」、「手書き」は「手動定義」、「歯抜け」は「欠番」「非連続」へ置き換えます。

システムの振る舞いや操作を日常会話の動詞で比喩的・口語的に表現せず、客観的かつ正確な技術表現へ置き換えます。

- 「呼ぶ」は「呼び出す」へ置き換えます。
- 「見る」は「参照する」「確認する」「検証する」へ置き換えます。
- 「書く」は「記述する」「設定する」へ置き換えます。
- 「出す」「出る」は「出力する」「表示する」「生成する」「発生する」へ置き換えます。
- 「消す」「消える」は「削除する」「終了する」へ置き換えます。
- 「落ちる」は「失敗する」へ置き換えます。
- 「走る」は「実行される」へ置き換えます。
- 「飛ぶ」は「遷移する」へ置き換えます。
- 「使い回す」は「再利用する」へ置き換えます。
- 「無い」は「存在しない」へ置き換えます。
- 「足す」は「追加する」へ置き換えます。
- 「選ぶ」は「選択する」へ置き換えます。
- 「置く」は「配置する」へ置き換えます。
- 「引く」は「検索する」へ置き換えます。
- 「決める」は「決定する」へ置き換えます。
- 「勝つ」は「優先される」「採用される」へ置き換えます。
- 「触る」「触れる」は「アクセスする」「直接参照する」へ置き換えます。
- 「捨てる」は「破棄する」へ置き換えます。
- 「キャッシュを落とす」は「キャッシュを破棄する」「解放する」へ置き換えます。
- 「食い違う」は「不整合が生じる」「一致しない」へ置き換えます。
- 「詰め直す」は「再配置する」へ置き換えます。
- 「一覧に乗る」は「一覧に含まれる」「一覧に記録される」へ置き換えます。
- 「ズレ」は「不整合」「乖離」へ置き換えます。

日常的・翻訳的な表記揺れを避け、リポジトリ全体で表記を統一します。

- 「デフォルト」は「既定値」「既定の」へ置き換えます。
- 「切替」は「切り替え」へ置き換えます (送り仮名の統一)。
- 長音を省略したカタカナ表記は避け、長音を付与します (「フィルター」など)。
- 「期待通り」は「期待どおり」へ置き換えます (公用文・技術文書の「どおり」平仮名表記)。
- 「以下の通り」は「次のとおり」へ置き換えます (参照方向の明確化と「とおり」平仮名表記)。

機能や効果を説明する見出しでは、口語調や願望・主観的表現を避け、客観的な名詞句を使用します。  
「〜が楽になる」は「〜性の向上」、「〜が速くなる」は「〜の迅速化」、「〜が強くなる」は「〜の強化」へ置き換えます。

業界標準の技術用語を優先し、方言的な言い回しや造語を避けます。  
配列要素の位置や検索では、「添字」「添字引き」ではなく「インデックス」「インデックス参照」を使用します。  
なお、テストや検証用の一時ファイルを表す「ダミー ファイル」という表記は、文脈上必要な場合に限りそのまま使用できます。

状態や代替動作は曖昧な日常語で濁さず、明確な用語で記載します。  
「欠けている」は「未設定」「未定義」、「読み替える」は「フォールバックする」「代替として使用する」と明記します。

## 重複

同じ規範や手順を複数の文書へ複製しません。  
唯一の正本を決め、入口文書と関連文書からリンクします。

要約表やチート シートを設ける場合は、正本との役割差を明記します。  
要約側に規範の根拠や長い説明を再掲しません。

## 確認

本規範に示す言い換えは代表例であり、表面的な語句置換にとどまらず、その考え方に基づいて 1 ファイルずつすべての文章を確認します。  
変更後は `text_style_jp.py --dry-run` を実行し、機械変換が日本語の意味を変えていないことを確認します。  
機械処理されない文脈依存の言い回し、用語選択、段落ごとの論点、です・ます調、重複、リンクを目視で確認します。
