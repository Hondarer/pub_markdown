# リンク解決の規則

この文書は、静的発行 (`make docs`) と動的発行 (`make livedocs` / `make servedocs`) が Markdown の相対リンクを処理するときの共通規則を定めます。  
静的発行と動的発行は出力形式が異なりますが、リンク先を論理ツリーで判定する規則は共通です。

## 論理ツリー

論理ツリーは、`mdRoot` と `mergeSubfolderDocs` で発行またはステージングの対象になった文書を、仮想パスへ配置したものです。  
追加ドキュメント ルートは `alias` を先頭に付け、メイン `mdRoot` と同じツリーへ結合します。

たとえば、`app/general/docs/vscode-variables.md` を `general=app/general/docs` として追加した場合、論理パスは `general/vscode-variables.md` です。

論理ツリーの対象外にあるファイルは、ワークスペース内に実在していても、どちらの発行でもリンク先として扱いません。  
この規則により、発行物が公開対象外のファイルへ依存することを防ぎます。

## 相対リンクの解決

相対リンクは、次の順序で解決します。

1. リンク元ファイルの実パスを基準にして対象を探します。
2. 見つからない場合は、リンク元の論理パスを基準にして対象を探します。
3. 対象が論理ツリーにある場合は、リンク元と対象の論理パス間の相対パスへ変換します。

同じディレクトリに `index.md` がない場合、`README.md` を `index.md` として扱います。  
`index.md` と `README.md` がない場合は、`SKILL.md` を `index.md` として扱います。

静的発行では、解決済みの文書リンクへ出力形式の拡張子を付けます。

- HTML: `.md`、`.yaml`、`.json` を `.html` へ変換します。
- docx: `.md`、`.yaml`、`.json` を `.docx` へ変換します。
- 動的発行: Markdown の拡張子を保持し、MkDocs に解決させます。

## 論理ツリー外の相対リンク

論理ツリー外、未生成、作業用、ソース コード、ヘッダー、ディレクトリへの相対リンクは、対象ファイルをどちらの発行へも追加せず、リンクを解除します。  
表示文字列を残し、その直後に元のリンク先を inline code として表示します。

```markdown
[ルート README](../../../README.md)
```

```text
ルート README (`../../../README.md`)
```

存在しない相対リンクを別のファイルへ推測して書き換えることはありません。  
参照先を発行対象に含める必要がある場合は、対象ファイルをドキュメント ルートへ移すか、`mergeSubfolderDocs` へ追加します。

## 変換しないリンク

次のリンクは、この規則による非リンク化の対象外です。

- `https://`、`mailto:` などの外部 URL
- `#anchor` 形式のページ内リンク
- Doxygen HTML への相対リンク
- 画像リンク
- コード フェンス内の記述

Doxygen HTML への相対リンクは、静的発行では Doxygen 出力ツリーへのリンクとして残します。  
動的発行では `/doxygen/` を提供する静的サーブの URL へ書き換えます。

## 実装の分担

`make docs` では、`link-common.lua` がパス解決と未解決リンクの非リンク化を行います。  
HTML 用と docx 用のフィルターは、出力拡張子だけを指定してこの共通モジュールを呼び出します。

動的発行では、`stage_livedocs.py` が同じ規則を Markdown ステージングへ適用します。  
Pandoc AST とステージング前の Markdown では処理単位が異なるため、実装は分離し、判定結果と表示規則をこの文書で共通化します。
