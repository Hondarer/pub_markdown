# 発行者と発行日時

## 概要

HTML 発行において、各ページのヘッダーに発行者と発行日時を表示します。  
発行日時には、そのページの元になったファイルの最終コミット ID を続けて表示します。

値はいずれも Git から取得します。静的発行と動的発行は同じ文字列を出します。

| 表示 | 内容 |
|---|---|
| 発行者 | 対象ファイルをコミットしたコミッター名 |
| 発行日時 | 対象ファイルの最終コミットの日時と、そのコミット ID |

## 表示する値

### 発行日時と最終コミット ID

日時と最終コミット ID は 1 つの文字列です。日時は RFC2822 形式です。

| 対象ファイルの状態 | 表示 |
|---|---|
| 追跡済みで、未コミット差分がない | 最終コミットのコミッター日時と、短縮コミット ID |
| 追跡済みで、未コミット差分がある | ファイルの更新時刻と、短縮コミット ID に `+` |
| 未追跡、または Git 管理外 | ファイルの更新時刻のみ |

未コミット差分がある場合は、表示している内容がコミット済みの内容と異なることを `+` で示します。

```text
Sat, 06 Sep 2026 12:34:56 +0900 5927f1d
Sat, 06 Sep 2026 12:34:56 +0900 5927f1d+
Sat, 06 Sep 2026 12:34:56 +0900
```

短縮コミット ID の桁数は Git が決めます。リポジトリの規模によって桁数が変わります。

### 発行者

対象ファイルをコミットしたコミッター名を、古い順に重複を除いて並べます。  
未コミット差分がある場合は、現在のユーザー名 (`user.name`) を末尾に足します。  
未追跡または Git 管理外のファイルでは、発行者を表示しません。

並べた人数によって表現を変えます。

| 人数 | 表示 |
|---|---|
| 1 名 | `登録者` |
| 2 名 | `登録者, 編集者` |
| 3 名以上 | `登録者, 最終編集者 et al.` |

## 設定

`pub_markdown.config.yaml` で表示を制御します。どちらも既定は有効です。

```yaml
# 発行日時の自動設定 (true / false)。デフォルト: true
autoSetDate: true

# 発行者の自動設定 (true / false)。デフォルト: true
autoSetAuthor: true
```

## 値の優先順位

Git から取得した値は、他に指定がない場合の既定値です。  
次の順に優先します。

1. Markdown のフロント マターの `author` と `date`
2. `publocal.yaml`、`pubpart.yaml`、`pubchild.yaml` の `defaults:` (静的発行のみ)
3. `autoSetAuthor` と `autoSetDate` による Git からの取得

## 静的発行での実装

発行処理はファイルごとに次のスクリプトを実行し、結果を環境変数へ入れます。

| 環境変数 | 取得元 |
|---|---|
| `DOCUMENT_AUTHOR` | `bin/get_file_author.sh` |
| `DOCUMENT_DATE` | `bin/get_file_date.sh` |

`bin/pandoc-filters/set-meta.lua` が、文書側にメタデータがない場合に限りこの環境変数を pandoc の `author` と `date` へ入れます。  
人数による表現の切り替えも同フィルターが行います。docx 出力では、著者を 1 行にまとめずリストのまま渡します。

テンプレート `styles/html/html-template.html` は、ナビバー右側の `.doc-info` に `$author$` と `$date$` を出します。

## 動的発行での対応

MkDocs による動的発行 (`make servedocs` / `make livedocs`) も、同じ値を同じ位置へ出します。  
解決はステージング時に行い、staged Markdown のフロント マターへ `author` と `date` を書きます。  
テンプレートは `page.meta` から読みます。この経路は Git 単一ページ リンクと同じです。

実装は `livedocs/bin/git_link.py` と `livedocs/bin/publish_info.py` です。  
前者が Git から事実を集め、後者が本書の規則で文字列へ整形します。

静的発行との違いを次に示します。

| | 静的発行 | 動的発行 |
|---|---|---|
| 事実の取得 | `bin/get_file_author.sh`、`bin/get_file_date.sh` | `livedocs/bin/git_link.py` |
| 文字列への整形 | `bin/pandoc-filters/set-meta.lua` | `livedocs/bin/publish_info.py` |
| 取得の単位 | ファイルごとに `git log` | リポジトリごとに 1 パスで一括取得 |
| `defaults:` による指定 | あり | なし |
| 著者のリスト保持 | docx 出力でのみリストのまま | なし (docx を出力しないため) |

詳細は [動的発行基盤](livedocs-design.md) の「発行者と発行日時」を参照してください。

## 補足

- 発行者と発行日時の解決対象は、発行するファイル自身です。Git 単一ページ リンクが行うフロント マター `git-origin` による元ソースへの差し替えは行いません。doxyfw が生成する `Files/` 配下の Markdown は未追跡のため、発行日時がファイルの更新時刻になり、発行者は表示されません。
- 発行者はコミッター (`%cn`) であり、作成者 (`%an`) ではありません。リベースやチェリーピックを行うと、作成者と異なる名前になります。
- 発行日時も同様にコミッター日時 (`%cD`) です。
