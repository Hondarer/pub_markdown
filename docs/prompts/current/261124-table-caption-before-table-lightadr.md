## LADR-001 Table: 行を表の直前に置く

決定者: Tetsuo Honda  
最終更新日: 2026-11-24

### 背景と課題

docsfw では、表のキャプションを表の直後の `Table:` 行で指定しています。発行結果ではキャプションを表の上に表示していますが、GitHub などで Markdown をそのまま表示すると、表題が表の下に表示されます。

### 得られた事実

- Pandoc の Markdown は `Table:` 段落を表の前後どちらに置いてもキャプションとして受け付けます。表が連続する場合は後置きの解釈が優先されます (pandoc 3.11 で確認)。
- Pandoc HTML と MkDocs は、いずれもキャプションを表の上に表示しています (`framework/docsfw/docs/table-caption.md`)。Pandoc の DOCX 出力も、表のキャプションを表の前に出力します (pandoc 3.11 で確認)。

### 決定

`Table:` 行は、表の後ろではなく表の直前に置く記法に変更します。`Figure:` と `CodeBlock:` は対象外とし、後置きのままとします。

## LADR-002 Pandoc での前置きキャプションの結び付け

決定者: Tetsuo Honda  
最終更新日: 2026-11-24

### 背景と課題

Pandoc の標準の解釈では、表が連続すると前置きの `Table:` が直前の表のキャプションになります。前置きのキャプションを確実に直後の表へ結び付ける方式を決める必要がありました。

### 得られた事実

- 表 A の直後に表 B 用の `Table:` を前置きすると、Pandoc の標準設定ではそのキャプションが表 A に付きます (pandoc 3.11 で確認)。
- `-f markdown-table_captions` を指定すると、`Table:` 行は通常の段落 (`Para`) として残ります (pandoc 3.11 で確認)。
- `Figure:` と `CodeBlock:` は、`codeblock-caption-line.lua` が通常の段落を直前のブロックへ取り込む方式で処理しています。
- `table_captions` を無効にすると、`Table:` 段落は解析の時点で通常の段落になります。Pandoc は箇条書きの項目に段落が 1 つでもあるとリスト全体を段落ごとの表示にするため、移行前と移行後の発行結果の比較で、1 ファイルの箇条書きの表示が変わりました (pandoc 3.11 で確認)。

### 決定

Pandoc に渡す直前に、前処理 (`bin_internal/table-caption-preprocess.py`) で、キャプションとして扱う `Table:` 段落を直後の表の後ろへ並べ替え、Pandoc の `table_captions` 拡張で取り込ませます。キャプションにしない `Table:` 段落と、表に隣接する行頭 `table:` / `:` の段落は、前処理でコロンをエスケープします。判定は `text_style_jp.py` と同じ共通モジュールで行います。

## LADR-009 移行時の表に挟まれた Table: 段落の解釈

決定者: Tetsuo Honda  
最終更新日: 2026-11-24

### 背景と課題

旧記法の文書には、表の直後のキャプションの次に別の表が続く箇所があります。移行の変換で、この `Table:` をどちらの表のキャプションとして扱うかを決める必要がありました。

### 得られた事実

- 2 つの表に挟まれた `Table:` が 13 ファイルに 15 か所あります (例: `framework/docsfw/docs/sample/repeatedly-test.md`)。
- 新記法の規則だけで変換すると、1 つ目の表のキャプションが失われ、2 つ目の表の前にキャプションが 2 つ並びます。

### 決定

移行の変換は旧記法として読み、表の直後の `Table:` 段落をすべて直前の表のキャプションとして、表の前へ移します。変換は後置きだけで書かれた文書に適用するものとし、前置きと後置きが混在する文書は適用の対象外とします。日常の確認では、直後が表の `Table:` を前置きとして正しいと判定します。
