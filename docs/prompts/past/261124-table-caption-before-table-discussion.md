### Q-001 前置きのキャプションを表へ結び付ける方式

**Status**

解決済み

**Question**

Pandoc 発行で、表の直前に置いた `Table:` 段落を、その直後の表のキャプションとして扱う方式をどれにしますか。

**Context**

- **経緯と背景**: Pandoc の Markdown は、`table_captions` 拡張 (既定で有効) により、`Table:` で始まる段落を前後どちらの表のキャプションとしても受け付けます。ただし、表が連続する場合は後置きの解釈が優先されます。手元の pandoc 3.11 で確認したところ、表 A の直後に表 B 用の `Table:` を前置きで書くと、そのキャプションは表 A に付きました。Lua フィルターは解析後の構文木 (AST) しか見られないため、どちらの向きで書かれたかを判別できません。

```markdown
| a | b |
|---|---|
| 1 | 2 |

Table: 表 B の表題のつもり

| c | d |
|---|---|
| 3 | 4 |
```

上の例を Pandoc の既定の設定で発行すると、`表 B の表題のつもり` は表 A のキャプションになり、表 B にはキャプションが付きません。

- **根拠資料**: `bin_internal/pub_markdown_core.sh` の Pandoc 呼び出しは `-f markdown+hard_line_breaks...` を使っています。`Figure:` と `CodeBlock:` は、`bin_internal/pandoc-filters/codeblock-caption-line.lua` が通常の段落として解析された行を直前のブロックへ取り込んでいます。
- **案 A**: 入力形式に `-table_captions` を追加して Pandoc の自動判定を止めます。`Table:` 段落は通常の段落として解析されるため、Lua フィルターが「`Table:` 段落の直後が表なら、その表のキャプションにする」処理を行います。ラベル `{#tbl:xxx}` の切り出しもフィルターで行います。`Figure:` と `CodeBlock:` と同じ構造の処理になります。手元で `-f markdown-table_captions` を指定すると、`Table:` 行が `Para` として残ることを確認しました。
- **案 B**: Pandoc に渡す前のテキストを書き換え、前置きの `Table:` 段落を表の後ろへ移してから、Pandoc の標準の解釈に任せます。テキスト処理でコード ブロックや箇条書きの字下げを正しく扱う必要があり、MkDocs の `stage_livedocs.py` と同等の処理を Pandoc 側にも持つことになります。
- **案 C**: Pandoc の標準の解釈に任せ、表を連続させるときは間に本文を置く規則にします。規則に反した場合は誤ったキャプションが付くため、検出の仕組みが別に必要です。

**Answer**

選択方式: 単一選択

- [x] A: (推奨) `-table_captions` で自動判定を止め、Lua フィルターで直後の表へ結び付ける
- [ ] B: Pandoc に渡す前のテキストで `Table:` 段落を表の後ろへ移す
- [ ] C: Pandoc の標準の解釈に任せ、表の連続を規則で禁止する
- [ ] D: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

確認済み。単一選択で A が選ばれています。`Figure:` / `CodeBlock:` と同じく、キャプション行を通常の段落として解析してフィルターで結び付ける構造になります。フィルターは pandoc-crossref より前に置きます。

### Q-004 キャプションと表の間の空行

解決済み

- **調査結果**: Pandoc の Markdown では、段落の直後に空行なしでパイプ表を書くと、表が段落の続きとして解釈されます。Python-Markdown (MkDocs) も同様に、段落の直後の表を表として認識しない場合があります。

```markdown

|---|---|
| 1 | 2 |
```

```markdown
Table: 空行なし (案 B)
| a | b |
|---|---|
| 1 | 2 |
```

- **案 B**: 空行なしも受け付けます。Pandoc と MkDocs の双方で、段落から表の行を切り離す前処理が必要になります。

**Answer**
