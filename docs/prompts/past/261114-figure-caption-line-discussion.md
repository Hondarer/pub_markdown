**Question**

**Context**

図のフェンスでは、PlantUML のソース内キャプションより `CodeBlock:` 行を優先する前例があります ([codeblock-caption.md](../../codeblock-caption.md) の「処理の流れ」)。

```markdown
![構成図の概要](images/arch.png)

Figure: システム構成 {#fig:arch}
```

- 案 A: キャプションは「システム構成」です。画像の `alt` 属性は「構成図の概要」のまま残します。
- 案 B: キャプションは「構成図の概要」です。`Figure:` 行は警告を出して通常の段落として残します。

- [ ] B: 代替テキストをキャプションに使い、`Figure:` 行は警告して通常の段落として残す。

### Q-002 代替テキストが空の画像に Figure 行を付けた場合

解決済み

**Question**

代替テキストが空の画像 (`![](x.png)`) に `Figure:` 行を付けた場合、画像の `alt` 属性をどうしますか。

**Context**

代替テキストが空の画像は、Pandoc でも MkDocs 前処理でも図になりません。`Figure:` 行がある場合は図にします (現行の合意内容 5)。  
このとき `alt` 属性を空のままにすると、HTML では装飾画像として扱われ、スクリーン リーダーが画像を読み上げません。Pandoc の implicit figure は、キャプションと同じ文字列を `alt` 属性に入れます。

- 案 A: `alt` 属性にキャプションの文字列を入れます。出力は代替テキストに「システム構成」と書いた場合と同じになります。
- 案 B: `alt` 属性は空のまま、キャプションだけを付けます。

**Answer**

選択方式: 単一選択

- [x] A: (推奨) キャプションの文字列を `alt` 属性に入れる。
- [ ] B: `alt` 属性は空のままにする。
- [ ] C: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)
