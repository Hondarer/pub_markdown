# Node.js モジュールの設定

docsfw は発行時に `bin/resolve-node-components.js` で npm コンポーネントを解決します。  
正しく設定された環境では、`bin/` への `npm ci` は走りません。  
欠けているコンポーネントだけをオンデマンドで入れ、処理を続行します。

使うパッケージの一覧と検出方法は [Node コンポーネント](../docs/node-components.md) を参照してください。

## 自動解決

`bin/pub_markdown_core.sh` と mkdocs プレビューの `vendor_assets.py` は、起動時に解決器を呼びます。  
人手で `npm ci` する必要はありません。  
事前に確認する場合は次を実行します。

```bash
node bin/resolve-node-components.js
```

欠けたパッケージを導入する場合は `--ensure` を付けます。

```bash
node bin/resolve-node-components.js --ensure
```

## Windows

Windows では Microsoft Edge が必須です。  
Edge が無ければ発行はエラーで終了します。  
Puppeteer 用 Chrome はダウンロードしません。

PowerShell で `npm` を実行すると、実行ポリシーにより `npm.ps1` が拒否されることがあります。  
その場合はコマンド プロンプトから実行してください。

## Linux

`PUPPETEER_EXECUTABLE_PATH` に実行可能な Chrome を指定すると、Puppeteer 用 Chrome をダウンロードしません。  
未指定、またはパスが実行できない場合は、npm コンポーネントの解決後に `$HOME/.cache/puppeteer` へ Chrome を導入します。

```bash
export PUPPETEER_EXECUTABLE_PATH=/usr/local/bin/chrome
export PUPPETEER_SKIP_DOWNLOAD=true
bash bin/pub_markdown_core.sh --workspaceFolder="$PWD"
```

`PUPPETEER_EXECUTABLE_PATH` は `pub_markdown_core.sh` の実行中に検証されます。  
無効なパスは警告を表示せず、スクリプトのプロセス内で未指定として扱います。  
呼び出し元シェルの環境変数は変更されません。

Chromium の依存ライブラリが不足していると、ダウンロードした Chrome でも起動に失敗します。  
過去バージョンが `.cache/puppeteer/chrome` に残ることがあるので、不要なら整理してください。
