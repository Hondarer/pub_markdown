# 日本語文書のレビューと推敲

Markdown 文書、ソース コードのコメント、メッセージ文字列などの日本語をレビューし、自然な言い回しへ推敲します。  
詳細な表現規範は `framework/docsfw/docs/japanese-technical-writing-guideline.md` の表現と確認の節を参照してください。

## 実行環境とモデルの選定

自身が Antigravity CLI ではなく、かつ `agy` (Antigravity CLI) が利用可能な環境である場合は、以下の手順で Antigravity CLI を利用してこの推敲作業を行ってください。

### モデルの選定基準

`agy models` の出力から **Gemini Flash 系の最新バージョン・Medium** を選択します。  
モデル名には CLI 内部 ID (`gemini-X.Y-flash-medium` 形式) を使用してください。表示名 (例: `Gemini 3.8 Flash (Medium)`) は `--model` に渡せません。

選定の優先順位は次のとおりです。

1. Gemini Flash 系の最新バージョン・Medium (例: `gemini-3.8-flash-medium`)
2. 上記が利用できない場合は、Gemini Flash 系で利用可能な最新バージョン・Medium

Pro 系や Low Effort は、日本語の推敲には推論能力と速度のバランスが不十分なため選択しないでください。

### ワークスペース コンテキストのロード

`--print` モードを単独で使用すると、ワークスペースの AGENTS.md、スキル、規範がロードされず、推敲品質が低下します。  
`--add-dir` でリポジトリ ルートを指定し、ワークスペースのコンテキストをロードしてください。

### プロンプトの構成

推敲対象の文章だけをプロンプトに渡さず、次の要素を含めてください。

- **役割と目的**: 日本語技術文書のレビューと推敲を行うこと
- **スキル名の指定**: `review-japanese-doc` スキルに従って推敲すること
- **対象の文章**: 推敲対象のファイル パス、またはインラインの文章
- **出力形式**: 修正後の文章、または修正箇所と理由の一覧

### 呼び出し例

```bash
# ファイルを指定して推敲を依頼する例
agy --model gemini-3.8-flash-medium --effort medium \
    --add-dir /path/to/repo \
    --print "review-japanese-doc スキルと japanese-technical-writing-guideline.md の規範に従い、次のファイルの日本語を推敲してください。修正箇所と理由を一覧で提示してください。対象ファイル: path/to/target.md"

# インラインで文章を渡して推敲する例
agy --model gemini-3.8-flash-medium --effort medium \
    --add-dir /path/to/repo \
    --print "review-japanese-doc スキルと japanese-technical-writing-guideline.md の規範に従い、次の文章を推敲してください。修正後の文章を返してください。

---
(推敲対象の文章をここに貼り付ける)
---"
```

> **注意**: モデル名の `3.8` の部分は `agy models` の出力に応じて最新バージョンに置き換えてください。

## 対象範囲と着手前の確認

対象ファイル (`.md` 文書、ソース コードのコメント、リソース定義など) や、特定ディレクトリ配下を再帰的に走査するかどうかについて、ユーザーから明示的な指定がない単独起動では、変更を開始する前に対象範囲と対象種別をユーザーとすり合わせてください。  
外部由来の配布物 (外部 OSS や第三者ライブラリなど) や、ビルド・ツールにより自動生成された成果物は推敲の対象外とします。自動生成された成果物に問題がある場合は、成果物を直接編集せず、その生成元 (生成スクリプト、テンプレート、元データなど) を対策してください。  
複数ファイルの一括推敲 (バッチ処理) を行う場合は、全文章を網羅的に確認するため相応のトークンを消費します。バッチ処理の着手前に 1 回のみトークン消費の旨をユーザーに確認してください。

## 推敲の原則

原文の意図や内容を変えずに、極めて自然かつ平易なビジネス ユースの日本語へ修正します。  
数字、固有名詞、コード識別子、断定の強さは変更しないでください。  
規範や本スキルに示す言い換えは代表例であり、表面的な語句置換にとどまらず、その考え方を用いたうえで 1 ファイルずつの全文章確認を行ってください。

推敲の観点と言い換え例は、`framework/docsfw/docs/japanese-technical-writing-guideline.md` の「文体と整形」と「表現」の節を正本として適用してください。

## 変更後の確認

Markdown ファイルを変更した場合は、対象ファイルごとに `text_style_jp.py --dry-run` を実行し、問題がなければ `--in-place` を実行してください。  
ソース コードのコメントやメッセージ定義を変更した場合は、ビルドやテストを実行し、構文エラーや振る舞いへの影響がないことを確認してください。  
レビューや提案だけの依頼ではファイルを変更せず、推敲案を提示して確認を求めてください。
